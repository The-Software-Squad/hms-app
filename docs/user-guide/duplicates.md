# Review and merge duplicate patients

Keep one identity after an explicit duplicate review.

**Who can do this:** System Manager

[All workflows](README.md)

## What this workflow does

Merging redirects the source patient’s links to the selected surviving patient and keeps an audit snapshot. It is a permanent administrative action, so compare both records first.

## Before you start

- System Manager access; both patient records reviewed; a clear reason.

## 1. Compare the records

Open each patient and compare identification, date of birth, contact details and clinical history. Choose which patient ID will remain.

## 2. Resolve blockers

Conflicting identification or birth dates, two active admissions, or financial records on the source prevent merging. Reconcile those issues before proceeding.

## 3. Open the source patient

Choose Actions → Merge Duplicate. In Keep this patient select the surviving patient, then enter a specific Reason.

## 4. Confirm the reviewed merge

Review the confirmation showing the target patient ID, then confirm only when the two records are the same person.

## 5. Check the surviving record

The target patient opens. Check its demographics and history, and use the HMS Patient Merge list to review the reason, actor and retained source snapshot.

## What success looks like

Only the selected target identity remains, and an HMS Patient Merge audit entry records the source and reason.

## Common problems and recovery

A shared name or phone number is not sufficient evidence. If a financial-record blocker appears, keep the records separate until billing identity has been reviewed.
